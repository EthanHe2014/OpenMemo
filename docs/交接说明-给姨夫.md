## 二、目前已经完成的部分

### 1. AI 自主对话（核心）—— 我最想请您保留的设计
AI 像真人一样聊天、追问、确认，一切由 AI 自己决定。架构上：**AI 负责所有"思考/说话"，服务端只做一件很轻的事**——解析 AI 输出的 JSON（回复什么、要不要记任务、几点提醒、提醒词），存库并到点朗读。没有模板、意图路由、拒绝话术。

这个设计是我踩过坑换来的：之前加过"写死"的对话逻辑，AI 反而胡言乱语/绕圈，后来全拆了。**如果遇到对话 bug，我推荐先改 SYSTEM_PROMPT（`openmemo/prompts.py`，多给 AI 指引），不太建议往 `conversation.py` 里加固定逻辑。**

### 2. 说话人识别（v1.1）
App 内登记（输名字→录 3 次音→Create ML 就地训练）；自动识别说话人，消息进各自专属会话，**人人数据隔离不串台**；未登记=访客，看不到任何已登记用户信息。

### 3. 情绪识别 + 声音事件（v1.2，全本地离线）
情绪（高兴/悲伤/生气/恐惧/惊讶/中性）+ 声音事件（笑声/哭声/咳嗽/掌声）；AI 会安慰/安抚/接梗/点破反话；气泡彩色情绪标签；**情绪/说话人/事件已落库**，翻旧记录还在（9/6 修好）。

### 4. 任务和提醒
大白话记任务；出行任务倒推出发时间；循环/重复/带日程任务；到点 Edge TTS 中文朗读 + iOS 本地通知。

### 5. 隐私与界面
侧边栏只显示干净名字，永不显示消息内容；暗色极光玻璃拟态；时间戳只在跨天/暂停≥30 分钟显示。小提醒：**App 界面不用 emoji/✓**，用 SF Symbols/纯文字。

## 三、怎么启动与维护

```bash
cd /Users/Ethan/Desktop/Projects/OpenMemo
# 启动（后台）
nohup .venv/bin/python -u -m openmemo.server > /tmp/openmemo_server.log 2>&1 &
# 健康检查
curl -s http://127.0.0.1:18890/api/health
# 停止（注意带 -sTCP:LISTEN）
kill $(lsof -tiTCP:18890 -sTCP:LISTEN)
```

几个踩过的坑，供您参考：
1. **项目在 `~/Desktop` 下时建议别用 launchd 自启**——macOS TCC 会拦 launchd 读桌面，Python 卡死且无弹窗。想开机自启：先把项目搬出桌面（如 `~/Projects/OpenMemo`），或给 launchd 全盘访问授权（需手动点）。普通终端启动没问题。
2. **不建议 `pkill -f "openmemo.server"`**——会把自己所在的终端一起杀掉。用上面的 kill 命令更安全。
3. 服务偶尔会退出，重启一次即可。
4. 推送 GitHub 走本地代理：`git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push origin main`（代理国外线路不通时可试直连）。
5. macOS 没有 `timeout` 命令。
